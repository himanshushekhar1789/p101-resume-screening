Problem Statement & Recruitment Bottleneck

Why modern automated screening systems fail recruiters and candidates alike

02 / 15

📉 Recruiter Cognitive Fatigue

High-volume applicant pools force recruiters to skim resumes in under 10 seconds. Manual evaluation suffers from inconsistency, fatigue, and subjective cognitive bias.

🔍 Lexical Phrasing Discrepancy

Candidates express skills with acronyms and synonyms (e.g. JS vs JavaScript, Postgres vs PostgreSQL, K8s vs Kubernetes). Keyword tools miss qualified talent.

⚠️ Black-Box AI Hallucinations

Direct generative AI prompting ("Rate this candidate 1-10") produces unexplainable scores, hallucinates unmentioned credentials, and is vulnerable to hidden prompt injections.

🎯 Central Project Requirement

"To design and build an auditable, transparent first-pass screening system that extracts structured profiles, proves every requirement match with verbatim textual citations, and keeps final hiring authority strictly with human recruiters."

Resolve aliases (k8s → Kubernetes) while protecting distinct technologies (Java ≠ JS, C ≠ C++).

4. Deterministic Requirement Matching

Authoritative mathematical rule engine evaluating skills, degrees, and tenure with zero hallucination.

Local sentence-transformers embeddings capturing conceptual context without overriding hard rules.

Orthogonal fusion: Rule Fit (30%), Semantic Fit (40%), Experience Fit (20%), and LLM-Supported Fit (10%).

7. Evidence-Grounded Skill Gaps

Categorize gaps into satisfied, missing, and insufficient with verbatim resume sentence citations.

8. Constrained LLM Explanations

Grounded natural language briefing with strict guardrails: zero automated hiring verdicts or speculations.

9. Recruiter Web Dashboard

Next.js 16 / React 19 interface providing audit tables, score breakdown grids, and human review notices.

10. Human-in-the-Loop Decision Support

Assistive audit tool; zero candidate ranking, zero leaderboards, and zero automated rejection decisions.

Deterministic Authority vs. Semantic Context

How P_101 prevents semantic similarity from falsely satisfying hard requirements

08 / 15

⚙️ 1. Deterministic Matcher

The Authoritative Gatekeeper

  • Resolves canonical skill aliases (k8s → Kubernetes).
  • Evaluates formal degree hierarchies (PhD > MS > BS).
  • Calculates exact tenure months from date ranges.
  • Protected Technology Matrix:
    Java ≠ JavaScript | C ≠ C++ | C ≠ C#
    Python ≠ PyTorch | React ≠ React Native

🌐 2. Dense Semantic Matcher

The Contextual Relevance Engine

  • Pretrained all-MiniLM-L6-v2 embedding model.
  • Computes 384-dimensional dense sentence vectors.
  • Cosine similarity score bounded between [0.0, 1.0].
  • Evaluates contextual alignment between candidate achievements and job responsibilities.

💡 The Architectural Proof: MySQL vs. PostgreSQL

Consider a candidate with MySQL applying for a role demanding PostgreSQL (Must-Have):

  • Semantic Matcher: Detects relational database context and awards high semantic similarity (0.55).
  • Deterministic Matcher: Strictly flags PostgreSQL as UNMET, maintaining must-have gating integrity.

📐 Separation of Experience (Invariants A–D)

General career tenure is strictly excluded from Rule Fit and Semantic Fit, eliminating double-counting and guaranteeing orthogonal measurements.

⚖️ Dynamic Renormalization (Invariant E)

If an optional component (such as LLM Fit) is disabled or unavailable, active weights automatically scale so that their sum equals exactly 1.0.

📌 Note: These percentages represent project-configured engineering choices, not claims of industry-optimal constants. Score does not predict hiring success.

Skill-Gap Auditing & LLM Guardrails

Actionable candidate feedback paired with strict responsible-AI boundaries

10 / 15

🔍 1. Skill-Gap Dimensions

  • Satisfied: Requirement met; anchored to verbatim resume quote.
  • Insufficient: Skill present, but candidate lacks required depth, version, or associated tenure.
  • Missing: Required skill completely absent from candidate profile text.
  • Not Evaluable: Subjective traits (e.g. "team player") reserved for human interviews.

🛡️ 2. Constrained LLM Guardrails

  • Fact Grounding: LLM only receives verified facts from the deterministic matching engine.
  • Zero Automated Verdicts: Strictly prohibited from stating "Hire", "Reject", or "Accept".
  • Anti-Speculation: Cannot assume unmentioned skills (e.g., assuming Django from Python).
  • Score Immutability: LLM has zero power to modify upstream computed scores.

⚠️ Human Oversight Disclaimer

P_101 is an automated screening assistant designed to aid human recruiters. Matching scores and LLM recommendations do not constitute hiring or rejection decisions.

System Limitations & Future Scope

Transparent academic acknowledgment of boundaries and roadmap enhancements

14 / 15

⚠️ Current Technical Limitations

  • CPU Cold-Start Latency: Initial PyTorch weight loading takes ~2s on first startup (sub-30ms warm).
  • Absence of Native OCR: Scanned image-only PDFs are rejected via 422 error; requires embedded text.
  • Taxonomy Boundaries: Emerging proprietary frameworks rely on semantics rather than aliases.
  • Single-Candidate Analysis: Workspace evaluates one candidate at a time; no comparative stack-ranking.
  • Synthetic Benchmarks: Synthetic evaluation data; does not establish real-world hiring efficacy.

🚀 Future Research Directions

  • Local OCR Pipeline: Integrate lightweight Tesseract / PaddleOCR to support scanned image PDFs.
  • Dynamic Ontology: Ingest public ESCO / O*NET skill graphs to expand alias mappings dynamically.
  • Recruiter Policy Sliders: Allow authenticated recruiters to configure scoring weights per role.
  • Consented Real-World Validation: Conduct IRB-approved empirical studies in active recruitment pipelines.
  • Asynchronous Batch Queue: Celery/Redis worker queue for bulk background resume processing.
